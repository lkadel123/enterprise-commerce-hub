Backend semantics verified from source: opaque key, customer-scoped, ≤200 chars, partial unique index + payload fingerprint, replay returns the original order. Regression tests added.
- **G17-04 Lifecycle type sync — IMPLEMENTED.** `OrderStatus`/`PaymentStatus` include `"Expired"`; `OrderDto` includes `expiresAt` and `refund: OrderRefund | null` (PENDING/SUCCESS/FAILED/UNSUPPORTED); `StatusBadge` maps `expired` → destructive and `initiated` → warning; history filter includes `Expired`; order detail renders `expiresAt`, refund card, and expired state (retry suppressed when expired). No invented status values.

backend (not just mocks that bypass the production flow), the E2E mock gateway

  always navigates to `/order-confirmation/:orderId`; payment initiation happens
  there via the "Pay now" button (server URL only). The storefront no longer
  navigates straight to the gateway from checkout, so the browser never decides

  passes, and posts the completed callback to the customer-scoped
  `/api/v1/customer/payments/:orderId/callback` rather than the admin callback.
